# Product Specs Index

Product specs define expected user outcomes, acceptance criteria, and measurable success.

## Active Specs
- [New User Onboarding](./new-user-onboarding.md)

## Spec Lifecycle
1. Draft in `docs/product-specs/`.
2. Link to an execution plan in `docs/exec-plans/active/`.
3. Implement and validate.
4. Move plan to `docs/exec-plans/completed/`.
5. Update quality/reliability/security artifacts if behavior changed.

## Required Sections for Each Spec
- Problem and user value
- Scope and non-goals
- Functional requirements
- Error and fallback behavior
- Observability and success metrics
- Acceptance criteria
